# Data Model: GitLab MR Review Skill

**Feature**: 015-ccd-gitlab-mr-review
**Date**: 2026-09-13
**Source**: [spec.md](spec.md), [research.md](research.md)

## Entities

### MergeRequest

The unit of work being reviewed. Read-only from the skill's perspective; the skill never creates or modifies the MR itself, only posts review artifacts against it.

| Field         | Type     | Source                       | Notes                                                         |
| ------------- | -------- | ---------------------------- | ------------------------------------------------------------- |
| iid           | integer  | `glab mr list --output json` | Internal ID within the project; used in all `glab mr` calls   |
| title         | string   | `glab mr view --output json` | Displayed in review summary                                   |
| state         | enum     | `glab mr view --output json` | `opened`, `closed`, `merged`; skill operates on `opened` only |
| source_branch | string   | `glab mr view --output json` | Must match current branch                                     |
| target_branch | string   | `glab mr view --output json` | Displayed in review summary                                   |
| reviewers     | string[] | `glab mr view --output json` | Usernames; checked for current user presence                  |
| web_url       | string   | `glab mr view --output json` | Reported in final output                                      |

**Validation rules**:

- State MUST be `opened`; closed or merged MRs are reported and the skill stops.
- Source branch MUST match `git rev-parse --abbrev-ref HEAD`; mismatch means wrong MR.

### ReviewFinding

An individual observation from the code review. Generated by the AI analysis step, grouped into the summary comment.

| Field       | Type    | Source        | Notes                                                         |
| ----------- | ------- | ------------- | ------------------------------------------------------------- |
| severity    | enum    | AI analysis   | `critical`, `suggestion`, `nit`, `fyi`; maps to Google labels |
| file_path   | string  | Diff analysis | Relative to repo root                                         |
| line_number | integer | Diff analysis | Line in the new file (post-image)                             |
| description | string  | AI analysis   | What the issue is and why it matters                          |
| rationale   | string  | AI analysis   | The engineering principle or best practice behind the finding |

**Validation rules**:

- Every finding MUST have evidence traceable to the diff or repository content (FR-012).
- Severity `critical` requires clear, unambiguous evidence; ambiguous issues get `suggestion` at most.
- `file_path` and `line_number` MUST reference actual lines in the MR diff.

### ReviewVerdict

The outcome of the review process, determined by user decision after AI analysis.

| Field     | Type   | Source             | Notes                                             |
| --------- | ------ | ------------------ | ------------------------------------------------- |
| decision  | enum   | AskUserQuestion    | `approve` or `request_changes`                    |
| findings  | array  | AI analysis        | List of ReviewFinding entities (empty if approve) |
| summary   | string | Template rendering | Rendered comment body posted to MR                |
| timestamp | string | System clock       | ISO 8601 format, included in posted comment       |

**State transitions**:

```
[AI Analysis Complete] → AskUserQuestion → [approve] → Post approval comment → Done
                                           → [request_changes] → Post summary comment → Done
```

### PreflightResult

Outcome of the environment validation step. Determines whether the review can proceed.

| Field            | Type    | Source                | Notes                                      |
| ---------------- | ------- | --------------------- | ------------------------------------------ |
| glab_available   | boolean | `command -v glab`     | False → stop with error                    |
| glab_authed      | boolean | `glab auth status`    | False → stop with error                    |
| is_git_repo      | boolean | `git rev-parse`       | False → stop with error                    |
| mr_exists        | boolean | `glab mr list`        | False → stop with "no open MR" message     |
| mr_iid           | integer | `glab mr list --json` | Populated only when mr_exists is true      |
| user_is_reviewer | boolean | Reviewer list check   | Determines whether to add self as reviewer |

## Relationships

- **MergeRequest** 1──* **ReviewFinding**: One MR produces zero or more findings during review.
- **MergeRequest** 1──1 **ReviewVerdict**: Each review invocation produces exactly one verdict.
- **ReviewVerdict** 1──* **ReviewFinding**: A `request_changes` verdict carries its findings; an `approve` verdict carries none.
- **PreflightResult** ──> **MergeRequest**: Preflight establishes which MR to review; failure stops before any MR interaction.

## Key Invariants

1. The skill never modifies the MergeRequest entity itself (no title, description, branch, or label changes). It only adds comments and approvals.
2. ReviewFinding entities are ephemeral — they exist only for the duration of one review invocation and are serialized into the posted comment. No persistence.
3. The current user identity is resolved once at preflight via `glab api user` and reused for reviewer-self-add checks. Never re-fetched mid-run.
4. All glab commands target the MR identified at preflight; no command accepts a different IID or branch mid-review.
